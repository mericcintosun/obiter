## The five illustrations and the component that renders each

Every asset is referenced by URL path through `next/image` with `unoptimized` and
explicit `width` and `height`, inside `components/plate.tsx` (`Plate`), which is
the one figure component on the route. The call sites:

| asset | rendered by | call site |
| --- | --- | --- |
| `/illustrations/ledger-rule.svg` | `Plate` | `app/page.tsx`, the fold, directly under the CTA |
| `/illustrations/precedent-compile.svg` | `Plate` | `app/page.tsx`, section 2, the compiler |
| `/illustrations/audit-revert.svg` | `Plate` | `app/page.tsx`, section 4, the record |

Meshy was not used. `mcp__meshy__*` is present in this session's tool list, but
every generation tool there produces a 3D mesh or a raster image and none of them
emits SVG, which is what the family has to be to carry the `#e9e0cd` hairlines at
any width; each call also costs credits that need a confirmation a non
interactive session cannot obtain. The four new assets are hand authored SVG in
the IDENTITY palette, which is the fallback the brief names.
